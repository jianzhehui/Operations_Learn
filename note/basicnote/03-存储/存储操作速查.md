# 存储操作速查

## 标准操作链路

```text
识别设备 -> 备份数据/元数据 -> 分区(可选) -> 创建文件系统或 LVM
        -> 临时挂载 -> 验证读写 -> 写入 fstab -> 验证开机挂载
```

## 选择分区与 LVM

| 场景 | 建议 |
| --- | --- |
| 容量固定、结构简单 | 传统分区可减少管理层次 |
| 预计扩容、跨盘组合、需要快照 | 使用 LVM |
| 大于 2 TiB 或需要较多分区 | 优先 GPT |
| XFS 文件系统 | 支持扩容，不支持缩容 |
| ext4 文件系统 | 可扩容；缩容必须离线并先缩文件系统 |

## 验证清单

1. `lsblk -f`：设备、分区、文件系统、UUID 和挂载点是否符合预期。
2. `findmnt`、`df -Th`：当前挂载和容量是否正确。
3. `pvs`、`vgs`、`lvs -a -o +devices`：LVM 层级及底层设备是否正确。
4. 写入 `/etc/fstab` 后执行 `mount -a`；不能等重启后才发现语法或设备错误。
5. 扩容后再次确认块设备、LV 和文件系统三层容量均已变化。

## 高风险提示

- `mkfs`、`wipefs`、分区表写入、`lvreduce` 都可能造成不可逆的数据损失。
- 操作前用序列号、容量、现有挂载和业务用途共同确认目标设备，不能只凭 `/dev/sdX` 名称。
- LVM 扩容顺序是底层设备/PV -> VG -> LV -> 文件系统；缩容顺序必须按文件系统能力制定，XFS 不能原地缩容。
- `parted` 的修改通常即时写入，执行前先备份分区表并准备恢复路径。
