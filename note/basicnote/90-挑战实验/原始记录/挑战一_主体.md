#### 4.2 如何检测服务是否生效

```shell
chronyc sources -v  				 #查看同步源状态
```

ms ^*  当前正在使用的主同步源。

name/ip address 203.107.6.88 ntp服务器地址。

stratum  ntp层级 。

poll 向该 NTP 源请求时间的间隔。

Reach 表示最近有几次成功,每次查询成功：右边补 1（二进制），失败补 0。

LastRx  上次成功接收到该源时间数据距今多少秒。

Last sample 当前样本计算出的系统时间相对该 NTP 源“慢/快”多少。

```shell
chronyc tracking 					 #查看同步源状态
```

Reference ID：当前参考时间源的 ID（后面括号里是解析出的 IP）。

Stratum：本机作为 NTP 客户端的当前层级。

Ref time (UTC)：最后一次成功从参考源更新系统时间的时间点（UTC）。

System time：当前系统时间相对 NTP 时间快/慢多少。slow of NTP time = 系统时间比 NTP 慢；fast of = 比 NTP 快。

Last offset：最近一次校时计算出的偏移量（秒）。

RMS offset：一段时间内偏移量的均方根，反映整体偏差大小。

Frequency：为了保持时间准确，纠正后本机时钟相对理想时钟的频率偏差（单位 ppm：百万分之一）。slow 表示硬件时钟略慢。

Residual freq：根据最近样本估算的剩余频率误差，越小越好。

Skew：对校正后频率不确定度的估计（频率“误差条”）。

Root delay：从本机到“最终时间源”往返的累计网络延迟。

Root dispersion：到最终时间源的累计时间误差估计，越小越好。

Update interval：当前两次校时之间的间隔（秒），会动态调整。

Leap status：闰秒状态。

Normal = 正常
其他值（如 Insert second, Delete second）表示即将插入/删除闰秒。

chronyc tracking 中：

#### 9.2 && echo ok || echo ng是否可以实现功能调换

不能实现调换

||和 &&的优先级是一样的，而且是从左到右依次执行的，而不是先执行la || echo ng 在执行echo ok

la失败（返回非0），因为前一个命令失败，执行echo ng，因为echo ng执行成功，执行&& echo ok

ls 成功（返回 0），所以 echo ng 不会执行，最后执行 && echo ok，于是只输出 ok。

#### 9.3 /dev/null  是怎么回事，经常用来做什么

dev/null 是linux系统里的一个特殊设备文件，写进去的东西全都会被丢弃，读出来永远是 EOF（什么也没有）。

从内核视角看，/dev/null`是一个字符设备：

写入：内核直接忽略数据，假装写成功。

读取：立刻返回“读完了”（EOF），返回 0 字节。

所以程序对 /dev/null 的读写都不会报错，却实际没有任何效果。

常见用途：

**丢弃输出（最常见）**

```shell
command > /dev/null      # 丢掉标准输出

command 2> /dev/null     # 丢掉错误输出

command &> /dev/null     # 丢掉标准输出和错误输出
```

**屏蔽交互输入**

让命令从 /dev/null读输入，相当于“立刻就读完了，没有输入”，从而防止命令等待用户输入而卡住。

**测试程序行为**

测试程序在“读不到任何数据”时的行为：

```shell
myprog < /dev/null
```

测试程序忽略输出时是否正常运行：

```shell
myprog > /dev/null 2>&1
```

#### 10.3 文件和文件夹的权限对应的数字是怎么来

chmod 里的数字权限是把「读/写/执行」三个权限用二进制加起来得到的。

单个角色（如 owner）权限数字是怎么来的
三种权限对应的值：

r（read，读） = 4
w（write，写） = 2
x（execute，执行） = 1
没有该权限则记为 0
一个角色（用户 / 组 / 其他人）有哪几个权限，就把对应值相加，本质上就是 3 位二进制（rwx）。

Linux 把权限分为三组：owner（文件所有者），group（文件所属组），others（其他所有用户）。
chmod 755 file 就是给这三组分别设置数字：

第 1 位：owner 权限
第 2 位：group 权限
第 3 位：others 权限

文件和目录的权限含义稍有不同
数字的计算一样，但含义有区别：

对文件：

r：能读文件内容
w：能修改/删除文件内容
x：能把文件「当作程序」执行
对目录：

r：能列出目录里的文件名（ls）
w：能在目录里创建 / 删除 / 重命名文件
x：能进入该目录（cd），能访问其中的文件

#### 12.3 使用sed -i修改软链接重启是否生效

硬链接（hard link）

可以理解为：多个文件名同时指向同一份数据。

删除一个文件名，数据不一定消失，只有当指向同一数据的所有硬链接都删除了，数据才真正从磁盘删除。

软链接（符号链接，symbolic link）

可以理解为：一个指向“路径”的快捷方式，类似Windows的快捷方式。软链接本身是一个小文件，里面保存的是“目标路径”的字符串；使用软链接时，系统会根据里面的路径再去找真正的文件。

指向路径，而不是指向数据

**修改后的内容会保存（重启后内容依然是修改后的），但是软链接(Soft Link)会被破坏，变成普通文件。**

详细原理解释：

sed -i（in-place editing）的工作机制通常是这样的：读取原文件内容，在内存或临时文件中进行修改，生成一个新的临时文件，将这个新文件重命名（mv）为原文件名，覆盖掉原来的文件。

**结果就是：**原来的软链接本身被删除了，同名的一个新普通文件被创建了，真正的源文件（软链接原本指向的文件）并没有发生任何变化。

重启服务后，这个“由软链接变身而来的普通文件”依然存在，修改依然有效，但它和原来的源文件已经断开联系了。

**合理操作**

使用 --follow-symlinks 参数

```shell
sed --follow-symlinks -i 's/旧内容/新内容/g' /path/to/symlink
```

找到真实路径进行修改

```shell
REAL_PATH=$(readlink -f /path/to/symlink)				# 获取真实路径

sed -i 's/旧内容/新内容/g' "$REAL_PATH"					# 对真实路径进行操作
```

## 1 vi里面的命令

#### 1.1 插入相关：i o a

i —— insert（在光标前插入）

o —— open（在下一行插入新行）

#### 1.2 移动相关：gg  GG

gg —— 跳到文件开头

GG —— 跳到文件末尾

#### 1.3 复制 / 粘贴：yy  y  p

yy —— 复制当前整行

可带数字：3yy 复制从当前行开始的 3 行

y —— 复制

单独一个 y不会立即复制，需要配合“动作命令”，比如：

yw：复制从当前光标到这个单词结尾

y$：复制从当前光标到行尾

0y$：复制整行（效果跟 yy类似）

y3w：复制接下来的 3 个单词

p —— 粘贴

功能：把刚才 y / yy / dd 等命令操作的内容粘贴出来

对行的行为：如果复制/删除的是一整行，p 会把那一行粘贴到当前行的下面

对字符的行为：如果只是复制了一小段，p 会在光标后面粘贴，P 会在光标前面粘贴

#### 1.4 删除/撤销：dd  x u ctrl+w

dd —— 删除当前整行

可带数字：3dd 删除从当前行起的 3 行；常配合 p 做“剪切+粘贴移动行”。

x (ctrl+w)—— 删除光标处字符

可带数字：3x 删除从光标开始的 3 个字符

u —— 撤销操作

## 2 为什么 sudo a.sh 会显示找不到命令

原因不在于权限，而在于 PATH 和执行方式。

当前用户已经是root，不需要再提权。

sudo是普通用户以root身份执行操作的。

sudo a.sh 会被当作找一个叫 [a.sh 的命令]，而不是当前目录下的文件。

默认情况下，当前目录 . 不在 PATH 里，所以 sudo 找不到它，就报：
sudo: a.sh: command not found
哪怕已经是 root，也一样。

正确的执行方式
在当前目录执行脚本，要写上路径：

```shell
./a.sh         # 推荐方式
bash a.sh	   # 指定解释器
```
