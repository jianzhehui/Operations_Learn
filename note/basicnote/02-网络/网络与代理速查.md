# 网络与代理速查

## 排查顺序

从低到高逐层确认，避免直接修改防火墙规则：

1. 网卡与链路：`ip link`。
2. IP 与掩码：`ip address`。
3. 路由与默认网关：`ip route`、`ip route get <目标IP>`。
4. DNS：`dig`、`nslookup` 或 `resolvectl query`。
5. 端口监听：`ss -lntup`。
6. 防火墙/NAT：`iptables -t nat -L -n -v --line-numbers`。
7. 应用访问与日志：`curl -v`，同时观察前后端日志。

## 三种转发方式

| 层次 | 典型实现 | 能否理解 HTTP | 真实客户端 IP |
| --- | --- | --- | --- |
| 三层/NAT | iptables DNAT/SNAT | 否 | 取决于是否做 SNAT 和网络回程 |
| 四层代理 | HAProxy TCP | 否 | 使用 PROXY protocol，后端必须显式支持 |
| 七层代理 | Nginx HTTP proxy | 是 | 使用 `X-Real-IP` / `X-Forwarded-For`，后端只信任指定代理 |

## NAT 操作要点

- 转发机必须开启 `net.ipv4.ip_forward=1`。
- DNAT 解决“请求发往哪里”，SNAT/MASQUERADE 解决“响应如何返回”。
- 规则中的入/出接口名必须来自现场 `ip link` 结果，不能照抄实验环境。
- 先查看现有规则并记录回滚命令，再添加规则；用计数器和抓包验证是否命中。

## 验证真实客户端 IP

1. 从独立客户端发起请求，避免把代理机自身地址误认为客户端地址。
2. 同时记录客户端、frontend 和 app 三端抓包或日志。
3. 七层代理检查请求头与 Nginx `real_ip` 信任范围。
4. 四层代理检查 HAProxy `send-proxy` 与 Nginx `listen ... proxy_protocol` 是否成对启用。
