# 文件服务选型与验证

## 协议选型

| 协议 | 主要用途 | 客户端体验 | 重点风险 |
| --- | --- | --- | --- |
| SMB | Windows/混合环境共享目录 | 可挂载、可浏览 | 认证、权限映射、SMB 版本 |
| NFS | Linux/Unix 主机间共享 | 可挂载为本地目录 | 导出范围、UID/GID、root squash |
| FTP | 传统文件传输 | 专用客户端 | 明文凭据与被动端口范围 |
| HTTP | 公开只读下载、镜像目录 | 浏览器和 `curl` | 目录索引、路径暴露、缓存 |

## 通用部署顺序

1. 明确“匿名/认证”“只读/可写”“允许来源”和审计要求。
2. 准备发布目录、属主、权限和 SELinux 上下文。
3. 安装并配置单一协议，先在本机验证服务监听和目录访问。
4. 放通所需端口，从独立客户端验证。
5. 检查服务日志，确认拒绝访问时能定位到权限、策略或网络层。

## 验证重点

- 验证匿名只读时，既要证明“可以读取”，也要证明“无法新建、覆盖或删除”。
- 防火墙开放范围应与客户端来源一致，不应为了排障永久关闭防火墙或 SELinux。
- 同一目录通过多种协议发布时，各服务的用户身份、权限模型和缓存行为可能不同。
